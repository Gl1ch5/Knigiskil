# Большая книга в FB2

Навык ведёт книгу от запроса до готового файла `.fb2`. Главный принцип: **никогда не писать книгу одним куском**. Всё делится на части → главы → пакеты, каждая глава — отдельный текстовый файл, а сборку, подсчёт страниц и проверку делают скрипты.

Скрипты лежат в `scripts/` рядом с этим файлом (дальше `$S` = путь к ним), только стандартная библиотека Python 3.8+.

## Быстрый режим: 2 шага, 1 писатель (по умолчанию)

Используй его, если пользователь не просит подробного плана или торопится.

1. **Концепция + библия.** Этапы 1–2 (стиль, сюжет «Подходит?», спойлеры, параметры), затем `book_init.py` + `book_plan.py skeleton` и один субагент заполняет `bible.md` (в «Сюжетных линиях» узлы привязаны к номерам глав, в «Синопсисе частей» — диапазоны глав), `title`/`synopsis` в `plan/parts/*.json` и поля `book.json`. Поглавный план (этап 4) **пропускается**.
2. **Один писатель.** Один субагент (`model: "haiku"`) пишет главы по порядку прямо по библии: каждая глава — 3 куска `cNNNN.txt`, `.2.txt`, `.3.txt` по ~6–7 тыс. знаков, после главы — `plan/summaries/cNNNN.md` (его память). Начинает с первой ненаписанной главы, так что если он остановился — запусти его снова тем же промптом. Затем `book_status.py` → `book_build.py --zip` → `book_validate.py`.

Названия глав берутся из строки `# …` в файле, поэтому пустые `title` в плане сборке не мешают. Полный режим (этапы 4–5 с параллельными пакетами) нужен для 4000+ страниц, когда важна скорость за счёт параллельности.

| Скрипт | Что делает |
|---|---|
| `book_init.py <dir>` | Создаёт проект книги: `book.json`, `bible.md`, `plan/`, `chapters/` |
| `book_plan.py skeleton <dir>` | Раскладывает объём по частям и главам → `plan/parts/part_NN.json` |
| `book_plan.py batches <dir> --size N` | Режет главы на пакеты-задания для субагентов → `plan/batches/*.md` |
| `book_plan.py show <dir>` / `check <dir>` | Печатает план / ищет незаполненные главы |
| `book_status.py <dir>` | Прогресс: сколько написано страниц, какие главы пустые/короткие |
| `book_build.py <dir>` | Собирает `.fb2` (и `--zip` → `.fb2.zip`) |
| `book_validate.py <file.fb2>` | Проверяет XML и обязательную структуру FB2 |

**Страница** = `page_chars` знаков с пробелами (по умолчанию 1800, как в обычной печатной книге). 1000 страниц ≈ 1,8 млн знаков, 4000 страниц ≈ 7,2 млн знаков.

## Этап 1. Изучение запроса

1. Выдели из запроса: жанр, стиль/автора-образец, объём, эпоху и место, героев, пожелания.
2. Если назван стиль («в стиле Дюма», «как у Толстого», «как Кинг»):
   - кратко сформулируй для себя и для пользователя, **что это за стиль** — 4–6 пунктов (см. `references/styles.md`: темп, тип героев, язык, композиция, приёмы, типичные сюжеты);
   - не копируй тексты автора и его персонажей — пишем **оригинальную** книгу в этой манере.
3. Придумай **краткую концепцию**: рабочее название, логлайн (1 фраза), 5–8 предложений сюжета, главный герой и антагонист, место/время. Без финала, пока не разрешены спойлеры.
4. **Спроси: «Подходит?»** (AskUserQuestion: «Подходит» / «Изменить …» / «Другой вариант»). Если нет — переделай и спроси снова. Не переходи дальше без одобрения.

## Этап 2. Уточнение пунктов — по одному, с подтверждением

Каждый пункт — отдельный вопрос (можно пачкой до 4 в одном AskUserQuestion), у каждого — вариант по умолчанию с пометкой «(Рекомендуется)»:

1. **Спойлеры.** «Можно ли показывать вам развязку и повороты в плане?» — Да, показывать всё / Нет, держать в секрете (тогда в сообщениях пользователю план без финала и тайн; полная версия только в `bible.md`).
2. **Объём:** сколько страниц (по умолчанию из запроса; минимум разумный — 100, навык рассчитан на 1000–4000+).
3. **Структура:** число частей/томов, примерная длина главы (рекомендуется 8–12 страниц).
4. **Название и автор:** название книги, имя автора/псевдоним для FB2.
5. **Повествование:** от 1-го или 3-го лица, один или несколько POV.
6. **Тон и рамки:** возрастной рейтинг, допустимая жестокость/романтика, счастливый/открытый/трагический финал.
7. **Жанр FB2** (код из `references/fb2_format.md`, например `adventure`, `prose_history`, `sf_fantasy`).

После всех ответов покажи **сводку параметров** и спроси последнее подтверждение «Начинаем писать?».

Ответы записываются в `book.json` (поля `title`, `author`, `genres`, `target_pages`, `spoilers_ok`, `style`, `pov`, `rating`, …).

## Этап 3. Проект и библия мира

```bash
python3 $S/book_init.py books/<slug> --title "…" --author "Имя Фамилия" --pages 4000 --genre adventure
```

Заполни `bible.md` (это единственный источник правды для всех субагентов):
- стиль: правила языка, длина фраз, доля диалогов, приёмы, запреты;
- мир: эпоха, места, социальное устройство, реалии;
- персонажи: имя, возраст, внешность, речь (манера, словечки), цель, тайна, арка;
- сюжетные линии и их узлы, тайны и когда они раскрываются;
- глоссарий имён и названий (чтобы субагенты не путали написание).

## Этап 4. План

```bash
python3 $S/book_plan.py skeleton books/<slug> --parts 8 --chapter-pages 10
```

Скрипт создаст `plan/parts/part_01.json …` (файл на часть) с нужным числом глав и целевыми страницами. Затем **заполни каждую главу**: `title`, `pov`, `summary` (3–6 предложений), `beats` (4–8 сцен), `ends_with` (крючок в конце). Большой план заполняй по частям: одна часть за раз, сохраняй файл после каждой. Для 4000 страниц (≈400 глав) это можно отдать параллельным субагентам: каждому одна часть, общий синопсис частей — в `bible.md`.

Проверь: `python3 $S/book_plan.py check books/<slug>` (незаполненные поля) и `show` — у каждой главы есть summary и beats, все линии доведены до конца.

Если `spoilers_ok = false`, пользователю показывай только названия частей и завязку.

## Этап 5. Написание пакетами

```bash
python3 $S/book_plan.py batches books/<slug> --size 5
```

Появятся `plan/batches/batch_001.md …` — готовые задания. Каждый пакет = 1 субагент (Agent tool, можно `model: "haiku"` для скорости). Запускай **параллельно** волнами по 10–20 агентов. Промпт субагенту:

> Ты пишешь главы книги. Прочитай `books/<slug>/plan/batches/batch_007.md` и выполни задание полностью. Не пиши пользователю текст глав — только сохраняй файлы. В конце коротко ответь: какие файлы созданы и сколько примерно знаков в каждом.

Правила для писателя (они же продублированы в каждом batch-файле):
- глава → `chapters/cNNNN.txt`; первая строка `# Название главы`; дальше абзацы, **один абзац = одна строка**;
- длинную главу пиши кусками: `cNNNN.txt`, затем `cNNNN.2.txt`, `cNNNN.3.txt` (сборщик склеит их по порядку) — каждый кусок 5–8 тыс. знаков;
- `* * *` — разрыв сцены; `> текст` в начале главы — эпиграф; `*курсив*`, `**жирный**`; диалоги через тире «—»;
- после главы — краткое содержание в `plan/summaries/cNNNN.md` (5–10 строк: что произошло, кто где оказался, что узнали) — это память для следующих пакетов;
- держаться `bible.md` и плана, не менять имена, не завершать сюжетные линии раньше времени.

Для связности: пакеты одной части пиши волнами по порядку, а новой волне давай в задании ещё и summaries предыдущих глав (скрипт `batches` сам добавляет ссылки на них).

## Этап 6. Контроль

```bash
python3 $S/book_status.py books/<slug>          # таблица прогресса
python3 $S/book_status.py books/<slug> --short  # только пустые/короткие главы
```

Главы короче 70% цели — дописать (новый кусок `cNNNN.K.txt` по beats, которые не раскрыты). Пустые — перезапустить пакет. Проверь выборочно стыки глав и имена по глоссарию.

## Этап 7. Сборка FB2

```bash
python3 $S/book_build.py books/<slug> --zip
python3 $S/book_validate.py books/<slug>/out/<slug>.fb2
```

Итог: `out/<slug>.fb2` (+ `.fb2.zip`). Части становятся вложенными `<section>`, главы — секциями внутри, эпиграфы, курсив и разрывы сцен переносятся в FB2-разметку, аннотация и жанры берутся из `book.json`, обложка — из `cover.jpg|png`, если есть. Отдай пользователю файл и итог: страниц, знаков, глав.

## Ориентиры по масштабу

| Страниц | Знаков | Глав по 10 стр. | Пакетов по 5 глав |
|---|---|---|---|
| 1000 | 1,8 млн | 100 | 20 |
| 2000 | 3,6 млн | 200 | 40 |
| 4000 | 7,2 млн | 400 | 80 |
| 6000 | 10,8 млн | 600 | 120 |

Файлы: `references/workflow.md` — шаблоны вопросов и сообщений; `references/styles.md` — как разбирать стиль автора; `references/fb2_format.md` — коды жанров и разметка FB2.
