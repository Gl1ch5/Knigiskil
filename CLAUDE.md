# Книги проекта

Этот проект — мастерская для нескольких книг. Каждая книга живёт в своей папке `books/<slug>/`, все они собираются в FB2 одним и тем же навыком.

## Структура

- `books/<slug>/` — одна книга:
  - `book.json` — метаданные (название, автор, жанр, объём, аннотация, ключевые слова);
  - `bible.md` — библия книги: стиль, мир, персонажи, сюжетные линии, тайны, синопсис частей, глоссарий. Единственный источник правды для писателя;
  - `plan/parts/part_NN.json` — части и главы (заголовки, краткие описания);
  - `plan/summaries/` — краткое содержание записанных блоков глав (память для продолжения);
  - `chapters/` — тексты глав (`cNNNN.txt` или `cNNNN-MMMM.txt`, первая строка главы — `# Название`);
  - `out/` — собранный `.fb2` и `.fb2.zip`.
- `books/README.md` — список книг проекта.
- `.claude/agents/book-writer.md` — агент-писатель, которому передаётся запись глав любой книги.
- `.claude/skills/large-book-fb2/` — навык и скрипты (`book_init.py`, `book_plan.py`, `book_status.py`, `book_build.py`, `book_validate.py`).

## Новая книга

1. Уточни у пользователя жанр, стиль-образец, объём в страницах и сюжет. Если пользователь дал всё сам, не задавай лишних вопросов — прими разумные значения по умолчанию и назови их в ответе.
2. Создай проект:
   ```bash
   python3 .claude/skills/large-book-fb2/scripts/book_init.py books/<slug> --title "…" --author "…" --pages N --genre <код>
   ```
3. Заполни `bible.md` (стиль, персонажи, синопсис, главы по номерам) и `book.json` (аннотация, ключевые слова).
4. `book_plan.py skeleton books/<slug> --parts P --chapter-pages 10`, затем заполни названия частей и синопсисы в `plan/parts/*.json`.
5. Запиши главы через агента `book-writer` блоками по 3–4 главы в файл. Для длинных книг используй `book_plan.py batches`.
6. Контроль и сборка: `book_status.py`, `book_build.py --zip`, `book_validate.py`.
7. Добавь книгу в `books/README.md`.

## Правила

- Каждую книгу пиши только в её папке. Не меняй чужие книги без просьбы.
- Текст глав не выводи в чат; в ответе — статус, объём и путь к файлу.
- Оригинальный текст: в стиле автора-образца, но без копирования чужих текстов и персонажей.
- Коммиты и пуши — в designated-ветку, PR создаётся как обычно (см. инструкции сессии).
